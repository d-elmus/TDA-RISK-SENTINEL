MIGRATION giotto-tda → ripser/persim (v2.1)
--------------------------------------------
AVANT (giotto-tda) :
  from gtda.time_series import TakensEmbedding
  from gtda.homology import VietorisRipsPersistence
  → TakensEmbedding.fit_transform() → (1, T', d)
  → VietorisRipsPersistence.fit_transform() → (1, n, 3)

APRÈS (ripser + persim) :
  from ripser import ripser
  from persim import wasserstein as persim_wasserstein
  → Takens manuel numpy (_takens_single) → (T', d)
  → ripser(window)['dgms'] → [H0_arr(n,2), H1_arr(m,2)]
  → _ripser_to_standard() → (n+m, 3) format interne
  → persim_wasserstein(h1_a, h1_b) → W₁ exact

AVANTAGES :
  - 10-50× plus rapide (C++ Ripser vs Python gtda)
  - W₁ exact (Hungarian matching) vs approximation 1D
  - Aucune dépendance TensorFlow
  - API plus simple et directe

ARCHITECTURE PIPELINE
---------------------
Prix (Yahoo Finance / GBM)
       ↓
Log-rendements r_t = ln(P_t/P_{t-1})
       ↓
Z-score glissant (fenêtre W, sans look-ahead bias)
       ↓
Takens Embedding multi-actifs (d, τ) + PCA → Nuage 3D
       ↓
ripser() : Filtration Vietoris-Rips → H₀, H₁
       ↓
Seuil dynamique IQR → filtrage bruit blanc
       ↓
Descripteurs par fenêtre :
  • persim_wasserstein (W₁ exact, Dₜ vs Dₜ₋₁)
  • Amplitude H₁ max
  • Entropie de Persistance E = -Σ pᵢ log₂ pᵢ
       ↓
TSS = 0.45·W₁ + 0.30·Amp + 0.25·(1-E)  [lissage EWM]
       ↓
Backtest : rotation SPY→GLD si TSS > θ
KPIs : Sharpe, MaxDD, CAGR, Calmar, Lead Time
       ↓
Dashboard Streamlit Pro (Vortex 3D animé, Radar, Risk Overlay)

MULTI-SCALE TDA — DÉTECTION PRÉDICTIVE (v2.3)
----------------------------------------------
OBJECTIF : Augmenter le Lead Time (anticipation krach) via divergence
           topologique entre deux échelles de temps.

ARCHITECTURE MULTI-ÉCHELLES :
  Données → run_multiscale_pipeline(W_fast=20, W_slow=100)
    ├─ Parallèle joblib.loky (2 workers simultanés)
    │   ├─ Pipeline W_fast=20j : micro-instabilités (TSS_fast)
    │   └─ Pipeline W_slow=100j : structure de fond (TSS_slow)
    ├─ _align_tss_to_prices() → alignement DatetimeIndex commun
    └─ compute_ptss() :
        ├─ ΔTSS  = TSS_fast − TSS_slow ∈ [-1, 1]
        ├─ P-TSS = norm(clip(ΔTSS, 0, ∞) × (1−TSS_slow)) ∈ [0, 1]
        └─ EW    = ΔTSS > rolling_μ(ΔTSS) + k·rolling_σ(ΔTSS)

MÉTRIQUES CLÉS :
  • ΔTSS > 0 : fracture topologique locale (TSS_fast > TSS_slow)
               → instabilité micro non encore propagée au niveau macro
               → FENÊTRE D'ANTICIPATION du krach
  • ΔTSS < 0 : convergence (détente ou stress systémique généralisé)
  • P-TSS ↑  : fracture forte + structure globale encore stable
               → signal prédictif le plus anticipateur
  • Early Warning : accélération anormale de ΔTSS → alerte à court terme

BACKTEST MULTI-ÉCHELLES (backtester.py) :
  run_multiscale_backtest() → 3 stratégies comparées :
    1. P-TSS Strategy   : déclencheur P-TSS > 0.35
    2. ΔTSS+ Strategy   : déclencheur ΔTSS > 0.15
    3. Combined (P-TSS + 0.5·EW) : stratégie hybride
  compute_lead_time_multiscale() : lookback élargi à 90j (vs 60j)

VISUALISATIONS (visualizations.py) :
  plot_multiscale_tss() : 3 panneaux
    Row 1 : TSS_fast + TSS_slow + ruban divergence (orange=fracture, bleu=convergence)
    Row 2 : ΔTSS (zones +/-) + P-TSS (ligne rouge vive)
    Row 3 : Early Warning (signal binaire)
  plot_multiscale_overlay() : Prix + TSS_fast + TSS_slow + P-TSS superposés

RÉSULTATS ATTENDUS :
  - Lead Time P-TSS > Lead Time TSS classique sur crises testées
  - P-TSS anticipe typiquement 2-8 semaines avant la rupture visible
  - Si gain nul : corrélation forte entre les deux échelles → marché
    sans découplage micro/macro → conditions TDA peu favorables
  NOTE : le Lead Time dépend des données disponibles et de la période.
         Sur simulation GBM sans structure de crise réelle, les deux
         échelles convergent (ΔTSS ≈ 0) → gain théoriquement nul.
